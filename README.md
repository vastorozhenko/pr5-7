# pr5-7: Secure Net App

Клієнт-серверний застосунок із захищеною передачею даних: TLS, bcrypt, JWT, ролі, TOTP MFA, захист від перебору паролів і флуду, JSON-журнали, CI з перевірками безпеки.

## Топологія

```
 ВМ threat-lab 192.168.0.192 (Ubuntu Server 24.04, Docker)
 └── мережа docker "lab" 172.28.0.0/24, шлюз 172.28.0.1
     ├── server  172.28.0.10   8080/tcp HTTP (лише /health, /echo-http)
     │                         8443/tcp HTTPS (усі ендпоінти)
     └── client  172.28.0.20   CLI-клієнт, бенчмарк, довіряє лише ca.crt
```

Клієнт отримує тільки `ca.crt`. Ключі CA і сервера, облікові записи, секрети MFA і журнали є лише на сервері.

## Запуск

```bash
bash server/scripts/gencerts.sh                      # CA і сертифікат сервера -> server/certs/
echo "JWT_SECRET=$(openssl rand -hex 32)" > .env     # секрет JWT не зберігається в репозиторії
docker compose up -d --build
cli() { docker compose exec -T client python client/client.py "$@"; }
cli echo --http --msg hi
cli tls-info --ca server/certs/ca.crt
```

## Команди клієнта

| Команда | Призначення |
|---|---|
| `echo --http --msg M` | ехо без шифрування (порт 8080) |
| `echo --https --msg M [--token T] --ca CA` | ехо через TLS; з токеном - захищений `/echo-https` |
| `tls-info --ca CA` | параметри TLS-з'єднання: версія, cipher suite, сертифікат, SAN |
| `login --user U --password P [--otp N] --ca CA` | вхід, виводить JWT |
| `mfa-login --user U --password P --otp N --ca CA` | вхід з одноразовим кодом |
| `whoami / admin --token T --ca CA` | захищені запити (`/admin/users` лише для ролі admin) |
| `refresh / logout --token T --ca CA` | новий токен / вихід (старий токен відкликається) |
| `forge --token T [--role admin] [--alg-none]` | підробка токена для перевірки контролю доступу |
| `mfa-setup --token T --ca CA` | секрет TOTP, otpauth URI і QR-код |
| `mfa-confirm --token T --otp N --ca CA` | підтвердження і ввімкнення MFA |
| `otp --secret S` | поточний код TOTP (замість застосунку-автентифікатора) |
| `brute --user U --wrong N --ca CA` | перебір паролів |
| `flood --token T --n N --threads K --ca CA` | паралельний флуд запитів |

`python client/bench.py --n 200 --ca CA [--user U --password P]` - порівняння HTTP і HTTPS, результат у `client/bench_results.md`.

`python3 tools/analyze_logs.py [--event E] [--user U] [--ip IP] [--level L] [--status N] [--since 10m] [--until T] [--suspicious] [--list]` - аналіз журналу.

## Політики безпеки

**TLS.** Власний CA (RSA 4096) підписує сертифікат сервера (RSA 2048, SAN: `server`, `172.28.0.10`, `localhost`, `127.0.0.1`). Клієнт перевіряє ланцюжок до `ca.crt` та ім'я сервера; без `--ca` з'єднання відхиляється. Порт 8080 без TLS обслуговує лише `/health` і `/echo-http`, решта запитів отримує 403 `HTTPS required`.

**Облікові записи.** Паролі зберігаються як bcrypt-хеші (cost 12) у `server/users.json`, ролі `user` і `admin`. Вхідні дані перевіряються: логін 3-32 символи `[a-z0-9_.-]`, пароль до 128 символів, OTP рівно 6 цифр. Для неіснуючого логіна виконується така сама перевірка bcrypt і повертається та сама відповідь, щоб не можна було визначити, чи існує користувач.

**JWT.** HS256, секрет з `.env` (мінімум 32 символи, без нього сервер не запускається), термін дії 15 хв. Перевіряються підпис, алгоритм (лише HS256, `none` відхиляється), `iss`, `exp`, обов'язкові поля, відповідність ролі в токені ролі користувача. `refresh` і `logout` відкликають токен за `jti`.

**MFA (TOTP).** Налаштування лише після входу: `mfa-setup` видає секрет і QR-код, MFA вмикається тільки після підтвердження правильним кодом (`mfa-confirm`). Повторно отримати секрет не можна. Код діє 30 с (допускається відхилення на ±1 крок), повторне використання коду відхиляється. Невірні коди враховуються як невдалі спроби входу. Секрети зберігаються в `server/data/mfa.json` (права 600, не в git).

**Перебір паролів.** 5 невдалих спроб для пари IP+логін або 20 для IP протягом 5 хв - блокування входу на 5 хв (429 з `Retry-After`). Під час блокування не приймається навіть правильний пароль. Інші користувачі й інші IP не блокуються.

**Флуд.** Token bucket на IP для всіх ендпоінтів, крім `/health` і `/echo-http`: 10 запитів/с, сплеск до 20, понад - 429.

Параметри змінюються через `.env` (див. `.env.example`).

**Журнали.** `server/logs/app.jsonl`, одна подія JSON на рядок: кожен запит (метод, шлях, код, IP, користувач, час), вхід і помилки входу, блокування, невалідні і прострочені токени, відмови в доступі, MFA, rate limit, помилки сервера. Паролі, токени, OTP і секрети не записуються.

## CI

`.github/workflows/security.yml` запускається при змінах у `server/`, `client/`, `tools/`, `requirements.txt`, `Dockerfile` і вручну:
- Bandit (SAST) для коду;
- pip-audit для залежностей;
- smoke-тест: генерація сертифікатів, запуск сервера, TLS з перевіркою CA, вхід, 200/403 за ролями, 429 при переборі.

Результати - у Summary запуску і в артефакті `security-reports`.
